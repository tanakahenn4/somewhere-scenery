【Git 保存手順】

対象フォルダーをターミナルから開く

① 変更確認
git status

② 変更を保存対象にする
git add .

③ PC内のGitに保存
git commit -m "今回の変更内容"

例：
git commit -m "カテゴリ選択機能を追加"

④ GitHubにも保存
git push


■ 基本は毎回この4つ

git status
git add .
git commit -m "変更内容"
git push

※ 必ず1行ずつ実行する。
※ git commit = PC内に復元ポイントを作る
※ git push = その履歴をGitHubにも送る

ここから実装したい機能をざっと書いていく
1.マーカー登録時に「題名」「メモ」「登録時の日付」を登録できるようにしたい
2.グーグルアースみたいに地図上のマーカーに登録時の題名を表示させる
3.それをグーグルアース及びアライバルスペースみたいにサイドパネルからも一覧表示させれるようにしたい
4.いいね機能もつけたい
5.最終的には登録されたマーカーに対してみんなで感想を書けるようにしたい(そこまで来るとログイン形式にする必要あると思う)
6.最終的にはログイン形式にしたいけど(Xとの連動とかでもいいかも)、最初のうちはマーカー登録削除に、個人個人が設定した削除パスワードで対応でもいいかな。それで何かあったとき用に、削除依頼項目もどこかにつけたい
7.レイアウトこだわりたい。グーグルアースの黒い画面の中に地図があるって感じのレイアウト結構好きかも
8.でもかっこいいレイアウトにこだわっているわけではなくて、たとえばかわいいに振り切るのもアリかなと思ってる。
どちらにせよ、アイコンは今のものから変更する必要がある

1.まず投稿データを豊かにする

今のマーカーに 題名 / メモ / 登録日 / カテゴリ / 削除用パスワード を持たせる。a
ここが土台。特に題名は今後の地図上ラベル・サイドパネル・検索結果・コメント欄の全部で使うから、かなり重要。a

2.地図上に「題名」を出す
これは相当効果が大きいと思う。今はアイコンだけだから「何かある」ことしか分からないけど、
古びた商店街
雨の日の高架下
猫がいる路地
みたいな題名が地図上に見えるだけで、急に「誰かが見つけた場所の集合」に見えてくる。Google Earthっぽさもここで一気に出る。a

3.サイドパネルを作る

ここがレイアウト面では最大の転換点になりそう。今のArrival.Spaceみたいに、画面の片側に投稿一覧を並べて、クリックするとその場所へ飛ぶ形式。
さらにマーカークリック時には同じパネルが「一覧モード → 詳細モード」に切り替わるようにするときれい。

4.そのあと、いいね

いいねは比較的単純に見えるけど、ログインなしでやる場合は「同じ人が何回でも押せる問題」がある。
最初は厳密性を求めず、ブラウザ単位で1回までくらいでもいいと思う。サイト初期なら「人気順を作れる」というメリットの方が大きい。

5.コメントは後半

コメントを入れると一気に運営サイトになる。荒らし、削除、投稿者識別、通報、管理画面が必要になってくる。
なので、これはログイン導入とほぼセットで考えていい。

6.ログイン前の削除方式

「登録時に削除パスワード」はかなり現実的だと思う。昔の掲示板っぽい方式だけど、このサイトの初期段階にはむしろ合ってる。
投稿時に削除キーを設定 → 後から自分の投稿を削除可能
さらに別途「削除依頼」を用意して、管理者が対応できるようにする。これはログイン実装までの橋渡しとしてかなり使いやすい。

7.レイアウトは“黒いフレーム＋地図”と相性がいい

Google Earth的な、ブラウザいっぱいに地図ではなく、周囲にUIの居場所がある構成は、このサイトには合いそう。
たとえば画面全体を暗めの背景にして、その内側に地図を置く。左にサイト名や検索、右に投稿一覧。
地図自体を少し小さくする代わりに「作品っぽい画面」になる。

8.かわいい方向も全然あり

しかも個人的には、完全にGoogle Earth風の硬質・黒基調に寄せるより、少しだけかわいさを混ぜた方がこのサイト固有の雰囲気が出そう。
「黒・チャコールグレーのフレーム」＋「やや柔らかいアイコン」みたいな中間案もある。今の猫や幽霊の絵文字っぽいアイコンは情報量が大きくて地図上でかなり主張するから、最終的には統一デザインに変えた方がいいと思う。

ここで一番大事なのは、先にレイアウトの完成形をある程度決めてから機能を載せることだと思う。

全国猫図鑑 — 公開サイトへの更新手順

対象フォルダーをターミナルで開いて、順番に実行。

git add .
git commit -m "Update site"
git push

git push が成功したら、少し待って公開サイトを更新する。

全国猫図鑑 Nekomap（公開版）

これで index.html だけでなく、icons 内の画像など変更したファイルもまとめてGitHubへ送られる。

GitHub Pagesは公開元のブランチへpushするとサイトを更新する仕組みにでき、反映には少し時間がかかる場合がある。

つまり普段はこの3行だけ覚えておけばOK。

git add .
git commit -m "Update site"
git push

なお、さっきのようにGitHub上で直接ファイルを変更した場合だけ、ローカルとGitHubの履歴がズレて fetch first が出ることがある。その場合は通常手順とは別に対処する。















これ、サイトのコンセプトとも結構相性いい

今作ってるものって、

「現実世界の中にある、誰かが気になったものを地図上に残す」

という方向になってきてるじゃん。

そこへさらに、

「現実には存在しないものを、Street Viewの世界にこっそり隠す」

というレイヤーが追加される。

例えば、

👻 ビルの窓に小さな幽霊
🐈 路地の奥に架空の猫
👁 電柱の陰から何か覗いてる
🧚 木の枝に小さな生き物
⭐ どこかに隠されたシンボル

とか。

しかも、見つけるまで地図上には正確な場所を表示しないようにもできる。

東京都内のどこかに5匹います

発見済み
■■■□□ 3/5

みたいな。

これだと完全に宝探しになる。

面白いのが「難易度」を物理的に作れるところ

でっかく置けば簡単。

小さくして建物の窓に置けば難しい。

後ろを振り返らないと見えない位置ならさらに難しい。

つまりStreet Viewそのものがゲームフィールドになる。

今のスクショで言えば、正面だけ見て進んでいたら気付かないけど、右側の店の商品棚をよく見ると小さな何かが混ざってる、みたいなのができたらかなり面白い。
